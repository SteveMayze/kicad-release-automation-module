# Changelog

All notable changes to this module are documented in this file.

The format is inspired by Keep a Changelog, and this project follows semantic versioning for module tags (`module-v#.#.#`).

## [Unreleased]

## [0.3.0] - 2026-11-11

### Breaking
- New managed files: `scripts/setup_kicad_cli_container.sh` and `scripts/package_release_artifacts.sh` (and `scripts/find_kicad_cli.py` is now listed as managed everywhere). Re-run `install.sh` and commit all managed files together; the workflow fails without the two new scripts.
- The release workflow needs Docker on the runner and pulls the KiCad container image (`KICAD_IMAGE`, default `kicad/kicad:10.0`) instead of installing KiCad.
- The release workflow writes to `.release-out/` and no longer reads or packages `gerber/`. Anything committed under `gerber/` is ignored by releases.
- `generate_release_artifacts.py` writes `release-manifest.json` into the output directory after each non-dry-run run, and refuses to run when `kicad-cli` is older than a selected board.
- `--dry-run` no longer updates `text_variables.RELEASE` or creates output directories.

### Added
- Added `gerber.additional_files` config support to copy extra files into the Gerber ZIP root.
- Added installed-version metadata and a local `check_release_automation_update.py` helper to query the latest module release.
- Added module smoke-test workflow for installer idempotency and local CLI dry-run validation.
- Added module release workflow for tagged module packaging and published checksums.
- Added uninstall helper script to remove managed files from target repositories.
- Added documentation for local pre-release validation and manual target upgrade policy.
- Added managed-file verification mode (`--verify`) in `check_release_automation_update.py`.
- Added multi-project configuration support via `projects[]` and `defaults.gerber`.
- Added project selection support in `generate_release_artifacts.py` via repeatable `--project-id`.
- Added targeted release-tag support in workflow template (`r/<project-id>/#.#.#`).
- Added a release manifest (`<output-dir>/release-manifest.json`, or `--manifest <path>`) listing the projects generated by a run.
- Added a preflight check that fails when `kicad-cli` is older than the KiCad version a selected board was saved with.
- Added `workflow_dispatch` input `dry_run` to build and upload ZIPs without publishing a release.
- Added managed script `scripts/setup_kicad_cli_container.sh` (creates the `kicad-cli` container shim) and `scripts/package_release_artifacts.sh` (builds ZIPs from the release manifest); the workflow template now calls both instead of inlining the logic.
- Added module CI job `e2e-real-kicad` that generates and packages Gerbers from KiCad 9 and KiCad 10 fixture boards with a real `kicad-cli`, plus `actionlint` over module and template workflows.
- Added optional `kicad.image` in `release-artifacts.json` to override the workflow's KiCad container image per target.

### Changed
- Clarified module vs target release tag conventions.
- Expanded installer metadata to schema v2 with managed-file versions and SHA256 checksums.
- Updated workflow packaging to emit one Gerber ZIP per selected project in multi-project mode.
- Kept plain `r#.#.#` tags in legacy single-project mode only when `project.path` config is used.
- Workflow template now generates into a clean `.release-out/` directory and packages one ZIP per manifest entry, so committed `gerber/` content is never published. ZIP names are unchanged.
- Workflow template passes inputs, ref name and step outputs to shell steps through `env:` instead of inline interpolation.
- Workflow template now runs `kicad-cli` from the official KiCad container image (`KICAD_IMAGE`, default `kicad/kicad:10.0`) through a shim, replacing the AppImage download and the `PATH` lookup step.

- Documented the container-based KiCad CLI, `KICAD_IMAGE`, the `kicad.image` override, the `dry_run` input and running the shim locally; removed the outdated note about the Ubuntu KiCad package.
- `install.sh` closing hint now mentions `projects[]` as well as `project.path`.

### Fixed
- `uninstall.sh` now also removes `scripts/find_kicad_cli.py`.
- `--dry-run` no longer rewrites `text_variables.RELEASE` in `.kicad_pro` files or creates output directories.
- Fixed mixed-platform path handling so Windows drive-letter paths work under WSL for configured project/additional file paths.

## [1.0.0] - 2026-08-10

### Added
- Initial reusable install/update workflow template for target KiCad projects.
- `generate_release_artifacts.py` entrypoint for Gerber and drill generation.
- Example `release-artifacts.json` configuration template.
